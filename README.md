# OpenAI — текущее подключение

В `.env` установлены `AI_PROVIDER=openai` и `OPENAI_MODEL=gpt-4.1-mini`. Вставьте ключ в `OPENAI_API_KEY=`. Перезапуск: `node --env-file-if-exists=.env server.mjs`. Без ключа действует явно обозначенный деморежим. Groq сохранён: для возврата укажите `AI_PROVIDER=groq`.

Три роли вызывают Chat Completions API со строгой JSON Schema. Проверяются отказ, обрезанный/пустой ответ, неподтверждённые сведения, неверный ключ и недостаточная квота. Для OpenAI используются OPENAI_MODEL и OPENAI_MODEL_ANALYST/INTERVIEWER/EDITOR; прежние AI_MODEL_* не влияют на OpenAI. Ключ не включается в архив. Реальные запросы требуют действующего ключа и доступной квоты API.

# Подключение Groq — текущий вариант

Вместо NVIDIA теперь по умолчанию используется Groq. Получите ключ на https://console.groq.com/keys и впишите в `.env`:

```dotenv
AI_PROVIDER=groq
GROQ_API_KEY=ваш_ключ
```

Три роли используют `qwen/qwen3.8-27b`. При необходимости модели меняются переменными `AI_MODEL_ANALYST`, `AI_MODEL_INTERVIEWER`, `AI_MODEL_EDITOR`. Перезапуск: `node --env-file-if-exists=.env server.mjs`. Ключ остаётся на сервере. Настройки NVIDIA сохраняются, но не используются при AI_PROVIDER=groq. Для возврата установите AI_PROVIDER=nvidia. Автоматического переключения и отправки данных другому сервису при ошибке нет.

Бесплатный тариф имеет лимиты: https://console.groq.com/docs/rate-limits . Реальное подключение Groq проверено: аналитик, интервьюер и редактор успешно обработали синтетический пример через Qwen 3.8 27B. Используется JSON-режим.

# Alem — HackAlem MVP

Веб-приложение: бизнес формулирует задачу, уточняет её с AI, подтверждает карточку и публикует в общем каталоге. Студенты отправляют предложения; бизнес вручную выбирает одну, несколько или ни одной команды.

## Запуск

Требуется Node.js 22.9 или новее. Внешние npm-зависимости отсутствуют.

```powershell
cd путь\к\alem
node --env-file-if-exists=.env server.mjs
```

Откройте http://localhost:3210. Без ключа NVIDIA приложение работает в явно обозначенном деморежиме. Данные сохраняются в `data/db.json` между перезапусками. Для проверки: `node --test --test-isolation=none`.

## NVIDIA: настройка реального AI

1. Скопируйте `.env.example` в `.env`.
2. Локально впишите свой ключ в `NVIDIA_API_KEY`. Не отправляйте ключ в чат и не коммитьте его. `.env` и данные включены в `.gitignore`.
3. При необходимости измените модели в трёх переменных `NVIDIA_MODEL_*`.
4. Перезапустите сервер командой `node --env-file-if-exists=.env server.mjs`. В AI-студии появится статус «Ключ настроен». Это означает наличие ключа, а не успешную проверку API.
5. В конструкторе введите синтетический пример и нажмите «Задать вопросы». Проверьте журнал агентов, затем заполните ответы и нажмите «Составить карточку».

Три агента — собственная логика приложения с разными ролями и моделями NVIDIA NIM, а не готовый внешний сервис агентов:

| Роль | Модель по умолчанию | Назначение |
|---|---|---|
| Аналитик | nvidia/nemotron-3-nano-30b-a3b | Извлечение известных полей |
| Интервьюер | nvidia/nvidia-nemotron-nano-9b-v2 | 3–7 уточняющих вопросов |
| Редактор | nvidia/llama-3.3-nemotron-super-49b-v1.5 | Карточка из ответов |

Подключение: `POST https://integrate.api.nvidia.com/v1/chat/completions`. Доступность и лимиты моделей зависят от NVIDIA. Справочник: https://docs.api.nvidia.com/nim/re/reference/llm-apis . Реальный доступ с пользовательским ключом не проверен при создании проекта.

Промпты и адаптер находятся в `ai.mjs`. Аналитик получает `{text}`, возвращает `{card}`; интервьюер получает `{text,card}`, возвращает `{questions:[...]}`; редактор получает `{text,card,answers:[{question,answer}]}`, возвращает `{card}`. JSON проверяется. Значения карточки должны быть точными фрагментами исходных текстов; новые факты отклоняются. Это консервативная защита: свободный пересказ моделью тоже отклоняется. Человек проверяет смысл и подтверждает публикацию. HTTP-ошибки, таймауты и неверные ответы показываются в интерфейсе без подмены успешным AI-результатом.

Без ключа возвращаются шесть шаблонных вопросов, исходное описание помещается в контекст. Автоматического переноса ответов в деморежиме нет: пользователь заполняет поля вручную. Интерфейс сообщает об этом.

## Архитектура

`public/` — интерфейс на JavaScript и CSS. `server.mjs` — Node HTTP API, валидация и атомарная запись JSON. `domain.mjs` — рейтинг и правила решений/этапов. `seed.mjs` — пять синтетических черновиков, карточек, команд и откликов. `ai.mjs` — оркестрация агентов. `test/` — проверки бизнес-правил, адаптера и сквозного HTTP-сценария с перезапуском.

MVP предназначен для локальной демонстрации одним серверным процессом. Роль переключается в интерфейсе; авторизация и разграничение прав на сервере не реализованы, как допускается заданием. Перед публичным размещением нужны аутентификация, проверка владения задачами/откликами, ограничение AI-запросов и полноценная БД. Сервер слушает только 127.0.0.1. Ключ доступен только серверу, статическая раздача ограничена четырьмя файлами.

## Рейтинг и каталог

Контекст и потребность — по 10; данные — 20; результат — 15; критерии успеха — 15; ограничения — 10; пользователи — 10; контакт и взаимодействие — по 5. Баллы начисляются за непустые поля после ручного подтверждения. Это проверка полноты, не семантической достоверности. До подтверждения показан только предварительный рейтинг. Уровни: 0–39 черновик, 40–69 рабочая, 70–89 готовая, 90–100 приоритетная.

Все опубликованные карточки доступны всем командам независимо от рейтинга. Каталог сортируется по убыванию баллов; есть поиск и фильтры по теме и готовности. Повторное редактирование обновляет рейтинг после подтверждения. Любая команда может отправлять отклики без ограничения количества. Выбор только ручной. Подтверждение одного демонстрационного этапа выбранной команды даёт +25 один раз для конкретного отклика. После подтверждения этапа решение фиксируется.

## Демонстрация до 5 минут

1. Создайте задачу с описанием «Магазин ведёт остатки в Excel. Автоматизировать учёт товаров».
2. Получите минимум три вопроса. Если нет ключа, явно обозначьте деморежим.
3. Заполните ответы, сформируйте/отредактируйте карточку. Введите название. Покажите разбивку рейтинга.
4. Подтвердите и опубликуйте неполную карточку. Она видна и доступна для отклика.
5. Добавьте данные, результат и критерии успеха; подтвердите, покажите рост рейтинга и позицию в каталоге.
6. Переключитесь на «Я — команда», откройте задачу, введите идею, план, срок и https-ссылку, отправьте предложение.
7. Переключитесь на «Я — бизнес», выберите команду вручную; при желании подтвердите этап и покажите баллы в разделе «Команды».

Пять исходных карточек имеют разную полноту. Ссылки example.com — явные синтетические примеры, не готовые прототипы.

## Разделение на троих

1. Интерфейс и конструктор: `public/app.js`, `public/style.css`.
2. API, рейтинг и AI: `server.mjs`, `domain.mjs`, `ai.mjs`.
3. Демо-данные, тесты, README и защита: `seed.mjs`, `test/`, этот документ. Изменения каталога согласовывать с участником 1, поскольку UI находится в одном файле.
